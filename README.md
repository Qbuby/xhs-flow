# xhsflow

小红书品牌 / 营销 / IP 图文内容的**自动生产线**。本地常驻服务，浏览器打开就能用：

```
作者主页链接 → 抓全量图文 + 图片 → 蒸馏成语料库 → 定时批量产稿 → 你审核 → 发到你的小红书
```

不开官方开放平台，全部走网页侧请求 + 浏览器自动化。**不生图** —— 配图要么从免费图库取，要么用代码按语料库的排版风格渲染。

---

## 快速开始

```bash
npm install          # 会自动下载 Chromium
cp .env.example .env # 填模型 key（至少填这个）
npm start            # 构建 + 启动 + 自动打开浏览器
```

打开 `http://127.0.0.1:8787`，按左边的导航走：

| 页面 | 做什么 |
|---|---|
| **总览** | 看登录状态、队列、事件日志；扫码登录 |
| **语料库** | 粘贴作者主页链接 → 抓取全部图文作品 → 蒸馏风格 |
| **创作台** | 选题、创作、定时任务（独立入口，不埋在语料详情里） |
| **草稿审核** | 逐篇看卡片大图 → 通过 / 拒绝 / 改文案 |
| **发布** | 发布准备台：文案一键复制、图片按序打包、创作中心一键打开，最后一步手动发 |
| **设置** | 探活、任务队列、事件日志 |

开发模式（前端热更新）：`npm run dev`

### 定时任务

在**创作台**配置，不在语料库里：

- **什么时候跑**：选「每天 / 每周 / 每隔几小时」+ 几点即可，不用碰 crontab；
  下方会显示「每天 09:30 执行 · 下次：10/11 09:30（18 小时后）」，
  crontab 原始表达式折叠在最后一行，需要时能查
- **每次产几篇**：1~5
- **选题池不足时自动补选题**：开了之后，池子空着定时任务也会先选题再创作，
  不会出现「定时任务每天在空转」的情况
- **品牌署名**：显示在每张卡片页脚

产出统一进「草稿审核」，等你点通过才会发出去。

```bash

npm run stop  # 停止后台运行的服务，并清理它拉起的浏览器
```

## 几个关键设计决策

这部分值得单独说，因为它们都不是默认选型。

### 1. 签名：不复刻算法，直接用页面自己的

小红书请求需要 `x-s` / `x-t` 签名头。生态里的做法是逆向实现（`xhshow`、`redbook` 等），但这套算法会定期轮换，谁都在追。

我们的浏览器本来就停在 `xiaohongshu.com` 上，**页面自己就带着最新版签名器**。所以 `server/src/xhs/signing.ts` 在运行时探测 `window._webmsxyw` 并调用它：

- 零逆向成本、零第三方代码
- 小红书一改算法，页面自动跟着改，**我们一行代码都不用动**
- 探针会尝试多种调用形态，并把每次尝试的结果记进事件日志，改版时能立刻看出是"没有这个全局"还是"有但形态变了"

### 2. 传输层：让浏览器替我们发请求

小红书靠 TLS ClientHello 指纹识别非浏览器客户端。成熟方案用 `curl_cffi` 伪装，**Node 没有等价能力**。

我们改用 Playwright 的 `context.request`：它走浏览器自己的网络栈（TLS 指纹是真 Chrome）、共享 cookie、且**不受 CORS 约束**。
> 最后一条很关键 —— 自定义头 `x-s`/`x-t` 会触发预检，页面内 `fetch` 直接 `Failed to fetch`，踩过这个坑。

### 3. 抓取：多级降级，不是单点

`user_posted` 是全行业公认脆弱的端点。我们按顺序降级，任一级可用即止，并把降级事件记进日志：

1. `/api/sns/web/v1/user_posted`（签名 API）
2. `/api/sns/web/v1/user/posted`（另一套命名）
3. SSR 页面 `__INITIAL_STATE__` 解析
4. 真实滚动主页，从 DOM 读

单篇详情同理：`/feed` → `/note/<id>` → SSR。

### 4. 视觉信息不让模型看图

配色、明暗这些用 `sharp` 离线算出来（`media/palette.ts`），作为**事实**喂进 prompt。这样更快、零 vision token、可复现，而且「主色是 `#F5E6D3`」这种客观信息本来就该从像素里取，不该让模型猜。聚合画像时把每篇的「视觉证据」行（版式 / 封面套路 / 图片作用 / 图上文字量）一起喂给文本模型，让它**归纳**视觉风格，而不是让它「想象」画面。

这里曾经有个**静默的错误**值得记：旧实现把 5bit 的 r/g/b 分别塞进 key 的 bits 15-10 / 9-5 / 4-0，然后 `key.toString(16)` 当普通十六进制打印。位宽对不上，于是白色 `(255,255,255)` 算出来是 `#007FFF` —— **一个蓝色**。它不报错、不崩、类型全对，只是 `note_images.palette` 里几乎每个 hex 都是错的。修法是：量化只用于**分桶去噪**，取色时把量化值还原回 8bit（`(v>>3)<<3`）再拼 hex。`verify-palette.js` 现在是常驻单测。

### 5. 语料检索用 FTS5 trigram，不用 embedding

检索目标是"找同风格 / 同题材的样稿"，这是**关键词匹配问题**，不是稠密语义问题。几百条量级下 trigram + 标签重合度打分，比拉 300MB 的 ONNX 运行时又快又准。

> 注意必须用 `trigram` 分词器：FTS5 默认的 `unicode61` 不切分 CJK，会把一整段中文当成一个 token，中文检索直接失效。

### 6. 卡片渲染用 Chromium，不用 satori

satori 不支持 `.ttc` 字体集合，而 Windows 默认的中文字体（微软雅黑 `msyh.ttc`）**正好是 `.ttc`** —— 走那条路必踩字体坑。用 Chromium 则系统字体栈免费拿、中文断行原生正确、grid / 阴影 / 渐变 / `mix-blend-mode` / 内联 SVG 全都正常。

尺寸固定 **1080×1440**（小红书原生 3:4），七种版式：`cover` / `quote` / `list` / `steps` / `compare` / `photo_text` / `cta`。

每张卡片分三层，互不干扰：

1. **纹理层**（`design/textures.ts`）—— `feTurbulence` 颗粒、半调网点、发丝网格、柔焦光晕。一层 `mix-blend-mode: overlay` 的噪点就能把「廉价大色块」变成「印刷品」，这是质感的分水岭。
2. **装饰层**（`design/motifs.ts`）—— 可组合的内联 SVG 件（分隔线、编号徽章、印章、走马灯条、竖排标签、页码…），全部绝对定位、不参与布局，所以永远不会把内容挤变形。
3. **内容层**（`layouts.ts`）—— 每个版式**自持骨架**（可以是分栏、出血、绝对定位层），不再共用「垂直居中一列文字」。

中文排版按 [heti](https://github.com/sivan/heti)（MIT）的规则落地：中文 `letter-spacing: 0`（加字距会散字）、只有纯拉丁才加 tracking、中文禁用斜体、中文段 `text-align: justify`。

**字体**：本机 `C:\Windows\Fonts\NotoSerifSC-VF.ttf` 实测存在，所以「衬线大字」这条手段不用捆绑字体就能用。但要注意一个实测发现 —— **Chromium 并不通过 `Noto Serif SC` 这个 family 名找到它**（`SimSun`/宋体/`serif` 都能正确落到宋体，`Noto Serif SC` 会一路 fallback 到微软雅黑）。所以标题字体栈里靠前的是 `"Noto Serif SC", "Source Han Serif SC", "Songti SC", SimSun, serif`，最终生效的是系统衬线（宋体系）。版式不会崩，只是气质比设计意图弱一点。

**卡片圆角**：旧的卡级 `radius` 字段直接删掉了 —— 截图是 JPEG，没有透明通道，卡片圆角只会被白角吃掉。现在卡片四角就是方的，需要「圆角感」的地方（徽章、印章、胶囊按钮）由装饰件自己做内切圆角，那些是实打实画在底色上的，不存在透明度问题。

### 7. 风格画像：不是设计形容词，是**在合同里做选择**

这一条前后改过一次，值得说明。

**旧版**：让模型自由填 `#hex` 与 `px`。结果 18 个字段里 8 个是坏的（`text_ratio` 渲染器一行没读、`palette[3..4]` 没人消费、`accent_style:'none'` 掉进 else 变成高亮、`background_image:'photo'` 与 `'none'` 输出完全相同的 CSS），剩下 10 个能表达的只有「颜色 + 字号 + 圆角 + 一种强调样式 + 一条线性渐变」。**给无限的颜色和字号选择，只会做出难看的东西。**

**现在**（`server/src/generate/design/`）：把设计系统写成机器可读的**契约**，模型在合同内做**选择**而不是自由发挥。

```
theme          三套视觉语言选一 —— still-paper 静纸 / signal-proof 实证 / bridge-canvas 图桥
palette_index  从该主题的固定色板组里选第几套（不能写 hex）
type_scale     字号阶梯三选一（不是具体 px）
density        密度档，一起决定边距与每卡条数上限
texture        纹理层（可 none）
motifs         0-3 个装饰件
accent_style   强调词的处理方式
```

三套主题是**配方不同**，不是换皮：静纸是暖纸底 + 衬线大字 + 大留白；实证是档案纸 + 细线 + 等宽元信息 + 印章，信息密度天然更高；图桥是满铺影像 + 黑边字幕，没有好图时退化成暗底大字。每套各自的色板、允许的纹理与装饰都是白名单，模型选错就回落到该主题的默认值。

已存的旧画像**不用重新蒸馏**：`design/migrate.ts` 按色相/明度/字号做确定性映射（深底 → 图桥、冷色低饱和 → 实证、其余 → 静纸），`toResolved()` 三种输入都能吃且永不抛。落库时统一归一成新契约，所以库里不会再出现两种形状。这条路径有回归测试兜着（见下方 `verify-legacy-spec.js`）。

### 8. 调度：DB 表 + ticker，不要 Redis

BullMQ 那套是为 Redis 持久队列设计的，单机常驻进程用不上，代价却是一个额外服务。`jobs` 表 + 15 秒 ticker 就够了，状态在 SQLite 里，重启不丢，还顺带获得完整历史可查。

## 防风控

小红书风控是真的会处置账号。2026-10-10 本项目的账号就吃到过一次：

> 处置结果：账号的流量曝光和商业权益受到限制（一周）
> 存在问题：账号下存在 AI 不规范使用的行为 —— 涉及账号浏览行为异常或不规律的情况，
> 如使用第三方工具（如 AI）进行模拟浏览，与真人操作习惯不符。

值得注意的是**触发原因不是内容，而是行为节奏**。把数据库里的时间戳翻出来对，机器的指纹非常刺眼：

| 现象 | 实测值 |
|---|---|
| 连续抓取时每篇笔记的间隔 | **精确 2.0 秒**，连抓十余篇不差毫秒 |
| 主页滚动 | 一步 `wheel(0, 3200)`，无中间帧、无停顿 |
| 鼠标轨迹 | 全程零移动，指针钉在原点而页面在翻 |
| 会话健康检查周期 | 严格 17 分钟一次（间隔直方图 17/17/17/9/17…） |
| 自动续抓计划 | 每天 04:00 整 |

所以现在的防护分两类。

### 一、节奏拟人化（`server/src/util/human.ts`）

- **一切时长走对数正态**：停顿、滚动、打字、甚至「走神」都从分布里抽。真人节奏是长尾的（多数很短、偶尔很长），均匀分布反而比固定值更容易被规律性检测抓出来。
- **滚动分格**：每格 70~270px、滚完停一下、偶尔回看一点。不存在一步 3200px。
- **动作之间必须有位移**：滚动前后会 `mouse.move` 到随机位置 —— 鼠标停着不动而页面在翻，是最廉价的机器特征。
- **阅读停留按内容长度算**：长文看得久，再叠抖动。这样就不会再出现「每篇恰好两秒」。
- **从主页点开笔记**，而不是逐个 `goto /explore/<id>`：真人就是这么看的（划过卡片 → 点进去 → 看完退回来）。referrer 也是主页而不是凭空冒出来的详情页。
- **逐字输入**：标题和正文不再用 `fill()`（一次性写入、零按键事件）。正文按段输入，段间停一下，每三段可能插一次长停顿。
- **非定周期的会话探活**：跑完再随机排下一次（40~90 分钟），安静时段跳过。

### 二、硬闸门

- **处置冷静期**：`settings.pause_until` 填一个日期时间，到期自动失效。**这一道连手动抓取也拦** —— 另外几道闸对手动操作只是提醒，这道不行，因为它拦的正是「反复去试它恢复没有」这个动作。已经按平台给的处置到期时刻（2026-10-17 15:09）设好了；可以在「设置 → 处置冷静期」修改或清空。
- **每日访问额度**（`DAILY_QUOTA`）：抓取 3 次 / 探活 8 次 / 登录 6 次，按本地日期计数，存在 `settings` 表里。用完就停到明天。
- **最小间隔**（`MIN_GAP_MIN`）：抓取 25 分钟、探活 45 分钟、登录 10 分钟。连点重试正是风控最想看到的，这里直接挡住（手动点会返回 429 并说明还差几分钟，不会静默失败）。
- **安静时段**：默认 `23:30-07:30`，自动任务在此期间不打开小红书。真人不会在凌晨反复访问创作中心。
- **定时计划避开整点与等间隔**：创作默认 `20 10 * * *`；自动续抓从 `0 4 * * *` 挪到 `40 10 * * *`（原来那个时刻还落在安静时段里，等于每次都白跑）。
- **用本机真 Chrome 而不是自带 Chromium**：自带 Chromium 的版本号不在 Chrome 的发布序列里、缺 Widevine，离线就能判定。UA 里的主版本号从 Chrome 安装目录实测读出（本机是 154）。
- **单并发**执行，不并发抓取；接口请求间隔仍是对数正态节流（均值 6 秒）。

操作台总览页有「今日防风控额度」进度条和冷静期横幅，随时能看到今天还能不能动。

### 自检

不用碰小红书就能验反检测基线是否成立（账号在处置期时也能跑）：

```bash
node server/dist/diagnostics/check-detection.js   # 真 Chrome？UA 与内核对齐？指纹补齐？
node server/dist/diagnostics/check-chrome.js      # 只查 Chrome 路径与版本号
```

`check-detection` 会打开一个 `about:blank`，把内核真实标识（CDP 的 `Browser.getVersion`）与页面看到的 UA 并排打出来，并逐项判定。跑不通时它会把具体哪一项不成立列出来 —— 这些是可以**离线判定**的特征，对不上时后面的拟人节奏做得再好也没用。

### 还是要说清楚的

以上都是**降低被识别的概率**，不是消除。平台明确表态「严格禁止任何利用技术手段模拟真人」，只要走自动化就一定承担账号风险。所以：

- **建议用小号**，别用主号
- 账号已被处置时，不要加大操作量去「试试它恢复没有」—— 那正好落进风控的观察窗口。本项目把这件事实体化成了冷静期闸门，就是不想让人手快。

### IP 被风控了怎么办

小红书会对 IP 出手，返回「安全限制 / IP存在风险」（错误码 300012）并以非 2xx 状态码响应。此时：

- **网页不渲染，扫码登录用不了**
- **但 API 仍然可用** —— 实测被限的 IP 照样能拿到正常业务信封

所以备用方案是**手动导入 Cookie**：在你自己常用的浏览器里登录小红书 → F12 Console 执行 `copy(document.cookie)` → 粘贴到操作台。整条流水线照常工作，完全绕开网页渲染环节。

## 发布：准备台 + 手动完成

**2026-10-12 起，自动化发布整体停用。** 自动发布、定时发布、一键发布都取消了（创作台的定时创作保留，只产草稿不发布）。

原因是账号在 2026-10-10 因「AI 模拟浏览」被限制曝光一周，官方点名的正是「用第三方工具模拟真人操作」。发布是全部功能里最重的机器行为 —— 打开创作中心、传图、逐字填表、点发布、再回管理页核对 —— 全程没有一个真人在回路里。拟人节奏能降低抓取的风险，压不住这个量级的暴露面。而平台明确表态要「真人分享真事、真感受」，那最后一步就该是真人完成的。

### 发布台怎么用

「发布」页 → 队列里点**准备发布**：

1. **文案**：标题 / 正文 / 话题标签三个按钮各自一键复制。正文是洗过的纯文本（无 `[[强调]]` 标记、无话题标签），直接粘贴进小红书编辑器即可，段落结构保留。
2. **图片**：点「下载图片 zip」，得到 `01.jpg / 02.jpg …` 按发布顺序命名的包。小红书的图片上传框按文件名排序，所以解压后全选上传就是正确的卡片顺序 —— 不用去记哪张在前。
3. **发布**：点「打开创作中心图文发布页」，粘贴文案、传图、点发布。
4. **登记**：发完把笔记链接贴回发布台点「标记为已发布」，草稿归档成「已发布」，记录里能直接点开。

不填链接也能归档，只是发布记录里没有直达链接。

### 为什么这样切

| 环节 | 以前 | 现在 |
|---|---|---|
| 想选题、写文案、配图 | 本机 LLM + 代码排版 | 不变（仍然是程序） |
| 打开创作中心、填表、点发布 | Playwright | **你** |
| 核对发布结果 | 回笔记管理页比对标题 | 你自己看到的那一篇 |

关键在最后一栏：发布这个动作本身是平台判定「真人还是机器」的核心信号，而它恰好是最容易交还给人、且人做起来最省事的一步（粘贴 + 全选上传 + 点一下）。省下的机器行为，换来的是这一步的干净。

`xhs/publish.ts` 及其实发验证记录（笔记 `6aca12cd000000001801a737`）全部保留，只是不再被调用；`verify-publish.js` 也保留，默认 dry run。将来若要调整策略，那是唯一跑通过全链路的代码。

### 诊断脚本

排查问题时很有用，都是真实跑过的：

```bash
node server/dist/diagnostics/verify-signing.js           # 端到端验证签名链路
node server/dist/diagnostics/inspect-signer.js           # dump 签名器真实返回值
node server/dist/diagnostics/inspect-login.js            # dump 登录入口候选选择器
node server/dist/diagnostics/check-detection.js          # 反检测基线自检（不碰小红书）
node server/dist/diagnostics/verify-corpus-transfer.js   # 语料库导入导出全链路自检（沙盒库，不碰主库）

# 渲染与版面（处置期也能跑，不碰小红书）
node server/dist/diagnostics/render-sample.js            # 渲染 7 种版式样张
node server/dist/diagnostics/render-sample.js --themes   # 三套视觉语言 × 7 版式矩阵
node server/dist/diagnostics/check-layout.js             # 版面几何自检：出画布 / 文字被裁 / 装饰压字
node server/dist/diagnostics/verify-legacy-spec.js       # 旧画像迁移 + 已发草稿回归渲染

# 纯单测（不需要浏览器）
node server/dist/diagnostics/verify-palette.js           # 调色板解码正确性
node server/dist/diagnostics/verify-stripemoji.js        # emoji 白名单（①②③ 保留，🔥 删除）
```

`verify-legacy-spec` 会做真实重渲染，其中 `photo_text` 卡会去图库取底图 —— 所以它是唯一一个会发外网请求的诊断脚本（Pexels / Wikimedia，**不是小红书**）。取不到就按设计退化成纯文字排版，不影响断言结果。

`check-layout` 值得单说一句：**「文字溢出画布」「元素互相压住」这两类硬伤是可以量化的**，不必靠肉眼。它逐张渲染后量三件事 —— 任何可见元素的 rect 是否超出 1080×1440、文字容器是否 `scrollHeight > clientHeight`、装饰层里的实心块是否与承载文字的元素相交。21 张样张现在是 0 问题。有意出血的装饰（金句卡那个只露一半的超大引号）用 `data-bleed="1"` 显式豁免，所以豁免是**点名的**，不是靠宽容阈值放过去的。

## 语料库导入导出（多设备迁移）

操作台「语料库」页右上角：**导出全部 / 导入**；来源详情页可以只导出某一位作者。产物是一个 zip（清单 JSON + 全部笔记图片），Windows 资源管理器 / 7-Zip 都能直接打开核对。

- **导出内容**：语料源、笔记、笔记图片、单篇蒸馏、作者画像、选题 —— 六张表加图片文件。
- **不包含**草稿和已发布记录：那是生成产物不是语料，且 `ref_note_ids` 存的是本机笔记主键，跨设备语义不同。要连草稿一起搬，直接拷贝整个 `data/` 目录（先停服务）。
- **`local_path` 不出门**：库里图片路径存的是绝对路径，换机器必失效。清单里只带包内文件名，导入时按本机 `data/media/corpus/<新笔记ID>/<序号>.jpg` 重新落盘、重写路径。
- **导入是合并不是覆盖**：按 `profile_url` 认来源、`(source_id, note_id)` 认笔记，已存在的一律跳过，只补缺。所以同一个包导两遍结果一致，也可以把两台设备各抓的一部分互相补齐。
- 主键（笔记 id 等）在导入时会重映射，蒸馏/画像/选题跟着新主键走，FTS 全文索引重建。
- 自检命令见上面 `verify-corpus-transfer.js`：真实导出 → 导入一次性沙盒库（`XHSFLOW_DATA_DIR` 重定向）→ 核对行数/图片字节/FTS → 再导一遍验证幂等。

## 已知限制

- **发布已改为纯手动**（见下节）。`xhs/publish.ts` 的自动化代码整体保留但不再被调用 —— 它是唯一经过实发验证的部分，将来若要调整策略还得靠它。
- **创作中心登录态与小红书网页端共用同一个浏览器 profile**，共用是特性（不用登两次），但也意味着同一个账号在两处的风控是叠加的。
- **只处理图文笔记**，视频笔记会被跳过。
- 原图分辨率受限于 CDN 下发的是压缩版本，不是用户上传的原始文件。
